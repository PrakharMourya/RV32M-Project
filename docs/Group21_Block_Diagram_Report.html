1. Top-Level Hardware Block Diagram (FULL PAGE)

The AutoVision-RISC-V architecture couples a cycle-accurate 3-stage RV32IM processor core with dedicated coprocessors, circular line buffers, 2D convolution accelerators, real-time edge classification, and split-screen 640×480 @ 60 Hz VGA compositing:

1. IF Stage

Synchronous PC register with Stall_PC gating. PCMux driven by PCSrcE selects PC+4 or PC_target. 16 KB Instruction BRAM (4096×32b).

2. ID/RegFile Stage

Control PLA decoding Op, Funct3, Funct7. 32-entry dual-read RegFile with write strobe RegWriteW. Immediate generator for I, S, B, U, J types.

3. EX Coprocessors

Hazard-controlled FwdA, FwdB muxes. 1-cycle DSP Multiplier (DSP48E1), Non-Restoring Divider FSM (≤ 34 cycles), RV32I ALU, and ExResMux.

4. MEM/WB & Accelerators

32-bit MMIO Crossbar, 2D Conv2D (1 px/cyc), Edge AI Classifier (<16.6 ms AEB), Split-Screen VGA, V2X Cipher. ResultW[31:0] loopback bus.

5. Verification Plans (≤ 6–8 lines total OR 3–4 bullets)

  • Arithmetic Unit Verification: Standalone testbenches (tb_multiplier.v, tb_divider.v) verify bit-exact 64-bit multiplication (MUL/H/HSU/HU) and validate non-restoring divider state transitions (≤ 34 cycles) under all mathematical corner cases including division by zero (x / 0 = −1) and 2's complement overflow (−231 / −1 = −231) with zero-cycle bypass.
  • Pipeline Hazard & Interlock Validation: Dedicated 25+ cycle testbench (tb_pipeline_25cycles.v) verifies zero-cycle RAW forwarding (WB → EX), multi-cycle non-restoring divider stall freezing (Stall_PC, div_busy), and branch misprediction pipeline flushing without data corruption.
  • Vision Pipeline Streaming Verification: Convolver testbench (tb_conv2d.v) streams synthetic step edges, verifying that 9 parallel MAC units compute Sobel edge gradients and Gaussian blurs at a sustained rate of 1 pixel per clock cycle (25 MHz).
  • Full SoC & FPGA System Validation: End-to-end SoC testbench (tb_autovision_soc.v) and physical Nexys A7 execution validate 115200-baud UART frame reception, real-time split-screen VGA rendering, 8-digit 7-segment display telemetry, and sub-frame (<16.6 ms) tri-color RGB Autonomous Emergency Braking (AEB) activation.

7. Risks & Challenges (≤ 5 bullets, 1 line each)

  • 1. Multi-Cycle Division Stall Synchronization: Synchronous pipeline register clock enable gating in hazard_unit preserves IF/ID state and prevents instruction loss during ≤ 34-cycle stalls.
  • 2. Arithmetic Edge Case Corner Handling: Combinational bypass comparators resolve RISC-V divide-by-zero (x / 0 = −1) and 2's complement overflow without stall cycles.
  • 3. Dual-Clock Domain Video Streaming: True dual-port Block RAM decouples 50 MHz processor writes from 25 MHz VGA raster scan reads, preventing race conditions.
  • 4. Line Buffer Boundary Hazards: Active line-valid pixel counters discard boundary pixels outside 160×120, preventing edge-wrapping distortions during 3x3 convolution.
  • 5. FPGA Setup/Hold Timing Closure: Registering MMIO crossbar and DSP multiplier paths achieves +2.410 ns setup slack at 50 MHz, ensuring zero timing violations.

8. Response to TA feedback (for the project abstract)

TA Feedback (Group 21): "The proposal mentions a 640 × 480 VGA display resolution and host PC streaming over UART, but it does not specify strict input size limits for incoming image."
  • 1. Strict Ingestion Resolution (160 × 120 Grayscale): Hardware video input is strictly bounded to 160 × 120 pixels (8-bit grayscale = 19,200 bytes/frame). Any excess data is automatically bounded by address counter wrapping at 0x4AFF.
  • 2. FPGA On-Chip BRAM Budget Protection: An uncompressed 640×480×8-bit frame requires 307,200 bytes (>50% of Artix-7 100T BRAM). The 160×120 budget consumes only 12.0 BRAMs (8.89%), leaving 91.11% of BRAM for instructions, data, line buffers, and stacks.
  • 3. UART Ingestion Throughput & Latency: At standard 115,200 baud (11,520 payload bytes/s), streaming 19,200 bytes requires exactly 1.66 seconds per frame, perfectly matching realistic ADAS obstacle updates without buffer overruns.
  • 4. Hardware 4×4 Upscaling to 640 × 480 @ 60 Hz: The VGA controller upscales video in pure hardware via 4×4 pixel replication (Xbram = ⌊Xvga / 4⌋, Ybram = ⌊Yvga / 4⌋), rendering split-screen video with zero CPU cycles and zero external DDR RAM dependencies.
